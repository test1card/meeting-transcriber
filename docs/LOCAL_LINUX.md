# Локальное распознавание в Omarchy

Отдельный профиль, установленный 6 октября 2026. Существующий Windows/WSL
профиль и GUI не изменены.

- ASR: Microsoft VibeVoice-ASR-Streaming-7B, сентябрь 2026.
- Говорящие: NVIDIA Nemotron-3-Diarization, 23 сентября 2026.
- Редактор: Qwen3-8B-FP8, локальный vLLM. Это более старая текстовая модель;
  ограничение по свежести применено к аудиомоделям.
- Скачанные ревизии и пути: `local-runtime.json`.
- Окружения: `.venv-asr` (vLLM 0.14.1, официальный плагин Microsoft),
  `.venv-diarization` (Transformers 5, Nemotron).

## Запуск

```bash
~/meeting-transcriber/scripts/meeting-local "/путь/Запись.m4a" \
  -o "$HOME/meeting-transcriber/outputs/Совещание-1" \
  --hotwords "Siemens NX,ANSYS,имена участников"
```

Этапы занимают GPU по очереди: VibeVoice → Nemotron → Qwen.
Сервисы слушают только localhost. Завершаются только процессы, запущенные этим
заданием. Если другая программа заняла порт 8765 или 8766, запуск остановится.
Повтор той же команды продолжает задание по контрольным точкам. Ctrl+C
сохраняет уже завершённые этапы/фрагменты. Изменение входа или конфигурации
требует новой папки результата.

Запись преобразуется в моно 16 кГц WAV. Исходный файл не меняется.
ASR обрабатывается фрагментами по четыре минуты; Nemotron использует глобальный
кеш говорящих внутри своего offline-прохода по всей записи. Метки VibeVoice
сохраняются для аудита, но не определяют итоговые метки говорящих.

Результаты этого экспериментального CLI:

- `documents/02_Исходная_стенограмма.md` — исходный текст ASR с метками Nemotron;
- `documents/03_Редакционная_стенограмма.md` — явно помеченная производная LLM;
- `_audit/` — исходные ответы, временные метки, очередь проверки, точные запросы
  и ответы редактора, использованные токены;
- `job.json`, `status.json`, `events.jsonl`, `checkpoints/`, `logs/` — состояние.

Это профиль транскрипции; генерация всех четырёх DOCX существующего GUI не
подключена к новым провайдерам. LLM не получает аудио и не меняет временные
метки/говорящих. Привязка текста делается по пересечению временных интервалов.
У ASR сегментные, не выровненные по словам границы; смешанные/перекрывающиеся
реплики отмечаются `UNRESOLVED` и попадают в очередь проверки. Имена участников
не угадываются. При отдельном стереоканале для каждого участника следует
выбрать обработку каналов вместо сведения в моно.

## Доступность GPU и FP8

Онлайн FP8 квантование декодера VibeVoice включено локальным дополнением к
официальному серверу (`--quantization fp8`); аудиоэнкодеры сохраняют заданную
производителем точность. Дополнение сохранено в
`runtime/vibevoice-fp8.patch`. Профиль использует `--cpu-offload-gb 12`
при загрузке и `--gpu-memory-utilization 0.90`. На RTX 5070 Ti 16 ГБ
проверены запуск сервера и обработка двух секунд тишины; веса заняли
12,1 GiB, общая занятая VRAM во время проверки — около 14,4 GiB.
Nemotron также проверен на CUDA; Qwen успешно исправил пунктуацию
контрольной русской фразы, сохранив говорящего и временные метки.
Это экспериментальный профиль:
качество FP8 и работа с настоящими длинными записями ещё не проверены. BF16
контрольный прогон на A100 должен выполняться отдельно без FP8.

Если `nvidia-smi` не видит RTX, CUDA-этапы не смогут стартовать. Этот установщик
не отвязывает GPU от Windows, не перезапускает графическую сессию и не
перезагружает ПК.

Для обработки через уже запущенные локальные сервисы:

```bash
scripts/meeting-local recording.wav -o outputs/check \
  --asr-url http://127.0.0.1:8765 \
  --llm-url http://127.0.0.1:8766 --llm-model meeting-editor
```

В локальном режиме адреса вне localhost отвергаются. Для теста только аудио
используйте `--no-edit`; для небольшого CPU-теста Nemotron добавьте
`--diarization-device cpu`. Веса скачиваются заранее, во время обработки
используются локальные файлы. Запись для проверки качества ещё не предоставлена.
