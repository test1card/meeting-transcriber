# Приложение «Документы встречи»

Tauri 2 + React/TypeScript интерфейс для офисного сотрудника. Пользователь выбирает
или перетаскивает одну запись, выбирает локальный или DeepSeek-режим и получает
четыре документа Word.

## Рабочий сценарий

1. Выберите MP4, M4A, MP3, WAV, MOV, MKV, AAC, FLAC, OGG или WebM.
2. Выберите **На этом компьютере** или **DeepSeek API**.
3. В локальном режиме выберите установленную модель Ollama.
4. Оставьте определение говорящих автоматическим или задайте диапазон количества.
5. Выберите папку результата и нажмите **Создать документы**.
6. Следите за этапами и прогрессом.
7. Откройте любой DOCX или папку результата на финальном экране.

Максимальная длительность записи — пять часов. Более длинный файл отклоняется до
запуска GPU-обработки с понятным предложением разделить его.

## Режимы приватности

### Локальный режим

WhisperX, MOSS, ECAPA и Qwen работают на компьютере. Консенсус, протокол,
редакционная и сокращённая версии создаются выбранной локальной моделью Ollama.
Внешний API не вызывается.

### DeepSeek API

Аудио и видео остаются локально. После явного согласия в API отправляется только
текст стенограммы. Если `DEEPSEEK_API_KEY` не задан, карточка API отключена и
приложение выбирает локальный режим.

## Надёжность

- статусы и контрольные точки сохраняются на диске;
- приложение восстанавливает прерванное задание после перезапуска;
- отмена не оставляет работающие дочерние процессы;
- Python, PowerShell и WSL запускаются без видимых окон терминала;
- четыре DOCX проверяются перед показом финального экрана;
- исходная полная стенограмма не заменяется сокращённой версией.

## Сборка

```powershell
cd apps/desktop
npm install
npm run check
npm run test:ui
npm run tauri:build:full
```

`npm run tauri:build:full` сначала обновляет чистые ресурсы рабочего контура, затем
собирает frontend и NSIS-установщик. Установщик появляется в
`src-tauri/target/release/bundle/nsis/`.

## Отладка

Для интерфейса используйте `npm run tauri dev`. Python-конвейер можно проверять из
корня проекта командой `python -m pytest -q`. Файлы задания, логи и контрольные
точки находятся в рабочей папке пользователя, а не в исходном репозитории.
